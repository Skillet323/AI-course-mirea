# Итоговый проект по курсу «Инженерия Искусственного Интеллекта»

В этой папке находится итоговый мини-проект по курсу.  
Проект демонстрирует применение методов и инструментов инженерии ИИ: работу с данными, модели, пайплайны, сервис, эксперименты и воспроизводимость.

  Система выполняет распознавание речи, diarization, извлечение задач, сопоставление задач с участниками и сохранение результатов в базе данных.  
  Дополнительно реализованы сравнение моделей извлечения задач, подсистема метрик и контур оценки по gold-разметке.

## 2. Структура проекта

Проект организован в следующей структуре:

- `requirements.txt` – зависимости проекта (библиотеки Python, необходимые для запуска).
- `report.md` – отчёт по проекту (постановка задачи, данные, эксперименты, результаты).
- `self-checklist.md` – чеклист самопроверки проекта перед сдачей.
- `notebooks/` – экспериментальные ноутбуки:
  - EDA, прототипы моделей, отдельные эксперименты.
- `src/` – основной код проекта:
  - модули для работы с данными;
  - запуск и обслуживание сервиса;
  - обучение и сравнение моделей;
  - служебные скрипты и сервисные модули.
- `data/` – демонстрационные/учебные данные:
  - **только открытые, синтетические или обезличенные данные;**
  - при необходимости – небольшие выборки для быстрого запуска.
- `configs/` – конфигурационные файлы:
  - `.yaml`, `.json`, `.env.example` и т.п.
- `tests/` – тесты (юнит-тесты, простые проверки).
- `artifacts/` – сохранённые результаты экспериментов, таблицы и отчёты.

В проекте дополнительно используются:
- `frontend/` — React + Vite интерфейс;
- `scripts/` — batch-скрипты для подготовки gold-разметки, сравнения моделей и очередной загрузки аудио;
- `data/gold/` — gold-аннотации встреч;
- `data/audio/` — аудиозаписи для экспериментов и демонстрации.

## 3. Требования и установка

### 3.1. Требования

- Python `>= 3.10`
- Node.js `>= 20` (для фронтенда)
- Docker (рекомендуется для воспроизводимого запуска)
- При необходимости: GPU и CUDA для ускорения Whisper

### 3.2. Установка окружения

```bash
# Перейти в папку проекта
cd project

# Создать виртуальное окружение
python -m venv .venv

# Активировать окружение:
# Windows:
.venv\Scripts\activate
# Linux / macOS:
source .venv/bin/activate

# Установить зависимости
pip install --upgrade pip
pip install -r requirements.txt
````

Если используется фронтенд отдельно:

```bash
cd frontend
npm install
```

Если нужен запуск с OpenRouter или diarization, заполните `.env` на основе `.env.example`.

## 4. Как запустить проект

### 4.1. Запуск backend

```bash
cd project
.venv\Scripts\activate
uvicorn src.main:app --reload --host 0.0.0.0 --port 8000
```

После запуска:

* UI: `http://localhost:8000`
* API: `http://localhost:8000/api`
* Swagger: `http://localhost:8000/docs`
* Health: `http://localhost:8000/api/health`

### 4.2. Запуск frontend отдельно

```bash
cd frontend
npm install
npm run dev
```

Фронтенд в режиме разработки обычно доступен на `http://localhost:5173`.

### 4.3. Запуск через Docker

```bash
cd project
docker build -t meeting-secretary .
docker run --rm -p 8000:8000 --env-file .env meeting-secretary
```

После этого:

* UI: `http://localhost:8000`
* API: `http://localhost:8000/api`
* Swagger: `http://localhost:8000/docs`

### 4.4. Проверка основных сценариев

```bash
curl -X POST http://localhost:8000/api/upload_meeting \
  -F "file=@data/audio/ES2002a.Mix-Headset.wav"
```

```bash
curl http://localhost:8000/api/metrics
curl http://localhost:8000/api/stats
curl http://localhost:8000/api/evaluations
```

## 5. Данные

В проекте используются данные AMI Meeting Corpus.

Основные файлы:

* `data/audio/` – аудиозаписи встреч;
* `data/gold/` – gold-аннотации в JSON;
* `artifacts/` – результаты экспериментов и сравнения моделей.

Файлы в `data/` используются как демонстрационные и исследовательские данные.
В репозитории не хранятся закрытые, персональные или чувствительные данные.

Если данные нужно скачать отдельно, это делается через отдельные скрипты:

* `scripts/build_ami_gold.py`
* `scripts/import_gold_annotations.py`

## 8. Ограничения и дальнейшая работа

В текущей версии проекта есть ограничения:

* diarization на шумных или очень коротких файлах может ошибаться;
* извлечение задач зависит от качества ответа LLM;
* часть моделей OpenRouter может быть недоступна из-за rate limit;
* оценка по gold-разметке отражает не все возможные сценарии.

Дальнейшее развитие:

* добавить ручную правку speaker-меток прямо из UI;
* расширить dashboard по метрикам;
* улучшить логику назначения исполнителей;
* усилить устойчивость task extraction;
* добавить дополнительные наборы данных для оценки.
